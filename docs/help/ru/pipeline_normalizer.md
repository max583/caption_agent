# Шаг 2: Нормализация

Второй шаг обработки: нормализатор превращает описание аналитика в готовую обучающую подпись.

## Для начинающих

Аналитик описал изображение в структурированном виде — теперь нормализатор берёт это описание и формирует из него строгую, однострочную подпись.

Что делает нормализатор:
- Начинает каждую подпись с trigger token вашего проекта.
- Выбирает формат подписи, соответствующий типу LoRA проекта: для персонажа это поза, одежда и обстановка; для стиля — техника рендеринга и палитра; для одежды — крой, материал и конструктивные детали предмета.
- Соблюдает правила caption policy: не добавляет слова о качестве изображения, не называет возраст персонажа по умолчанию.
- Если предыдущая попытка получила замечания от быстрой проверки — нормализатор видит их и исправляет подпись при следующей попытке.

Итоговая подпись — одна строка текста. Именно она попадёт в обучающий датасет.

## Для опытных пользователей

Нормализатор выполняет LLM-вызов с системным промптом, в который подставлены: trigger token проекта, тип LoRA, инструкции из caption policy проекта (если заданы). Входные данные — вывод аналитика и контекст батча (source_type, branch).

Структура подписи зависит от типа LoRA. Каждый тип имеет отдельный промпт нормализатора со своим шаблоном слотов. Trigger token обязателен для всех типов и всегда стоит первым; остальные слоты различаются. Полный список шаблонов — в разделе [Форматы подписей по типам LoRA](pipeline_normalizer_formats.md).

Если предыдущая итерация нормализации получила замечания от быстрой проверки, они передаются обратно нормализатору как feedback. Нормализатор предпринимает ещё одну попытку — исправляя выявленные нарушения, не добавляя новых.

Политика подписей, действующая на этом шаге:

- никаких style-токенов (photorealistic, cinematic и т.п.) — для всех типов
- обстановка описывается категорией места, не конкретными деталями — для character, face, pose, creature
- возраст не упоминается по умолчанию — для character, face
- обнажённость на кадрированном портрете описывается как "bare shoulders visible" — для character, face
- подписи к референс-изображениям используют фиксированный формат — для character

> **Для clothing LoRA:** детальное описание каждого атрибута предмета одежды является целью обучения, а не нарушением. Носитель упоминается только как контекст посадки.

Нормализатор должен вернуть ровно одну строку текста. Пустой ответ, JSON или ответ из трёх и более строк считается невалидным — запрашивается повторная попытка.

## Влияние на рабочий процесс

Результат нормализатора — поле `normalized_caption` у записи изображения. После нормализации подпись сразу же проходит быструю проверку. Если та возвращает замечания — нормализатор запускается снова (до исчерпания лимита попыток, заданного в настройках).

Подробнее о лимитах попыток — в разделе [Параметры проекта](ref_project_params.md). Подробнее о правилах проверки — в разделе [Быстрая проверка](pipeline_rule_checker.md).
