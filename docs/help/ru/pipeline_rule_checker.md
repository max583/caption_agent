# Шаг 3: Быстрая проверка

Третий шаг обработки: быстрая проверка ищет нарушения правил в тексте подписи — без обращения к LLM.

## Для начинающих

После того как нормализатор написал подпись, быстрая проверка читает её и смотрит: не нарушает ли она базовые правила. Эта проверка работает быстро — она не отправляет запросы в языковую модель, а анализирует текст напрямую.

Что проверяется — зависит от типа LoRA проекта, но в любом случае проверяются:
- Начинается ли подпись с trigger token.
- Нет ли слов, описывающих качество изображения («реалистичный», «кинематографичный»).
- Нет ли отрицательных описаний («без морщин», «нет артефактов»).
- Нет ли нескольких персонажей там, где должен быть один.

Дополнительные проверки — например, наличие типа кадрирования или ракурса — включены только для тех типов LoRA, в которых эти элементы обязательны.

Если нарушение найдено — формируется предупреждение с кодом, и нормализатор получает шанс исправить подпись. Если лимит попыток исчерпан — предупреждение остаётся в записи изображения, и финальное решение принимаете вы при ревью.

## Для опытных пользователей

Быстрая проверка — чисто детерминированная: регулярные выражения и логика, без LLM. Это позволяет запускать её на каждой итерации нормализатора без дополнительных затрат.

Коды предупреждений:

| Код | Условие |
|---|---|
| `TRIGGER_MISSING` | Подпись не начинается с trigger token |
| `NEGATIVE_WORDING` | Обнаружено отрицательное описание |
| `MULTI_CHARACTER` | Аналитик обнаружил других персонажей |
| `STYLE_TOKEN` | Обнаружен style/quality токен (кроме type=style) |
| `AGE_PHRASE` | Запрещённая возрастная фраза (character, face) |
| `ADULT_BRANCH_MISMATCH` | Взрослый контент на ветке identity (character) |
| `IDENTITY_OVERCAPTION` | Названа стабильная черта идентичности (character, face, creature) |
| `NUDE_ON_CROPPED_PORTRAIT` | «nude»/«naked» на кадрированном портрете (character, face) |
| `SOURCE_REF_PATTERN_VIOLATION` | Нарушен формат подписи к референс-изображению (character) |
| `FRAMING_INVALID` | Отсутствует канонический тип кадрирования (character, face, clothing, creature, pose) |
| `VIEW_INVALID` | Отсутствует канонический ракурс (character, face, clothing, creature, pose) |
| `SLOT_MISSING` | Не хватает обязательных слотов (character, clothing, creature, object) |
| `SETTING_OVERSPECIFIC` | Обстановка описана чрезмерно конкретно (character, clothing, creature, object) |

Первые три кода (`TRIGGER_MISSING`, `NEGATIVE_WORDING`, `MULTI_CHARACTER`) применяются ко всем типам LoRA. Остальные коды гейтируются по типу LoRA: в скобках после описания указано, для каких типов код активен.

> **Для type=style:** проверяется только TRIGGER_MISSING, NEGATIVE_WORDING и MULTI_CHARACTER — почти все остальные коды не применимы к подписям, описывающим визуальную технику.

Паттерны для `IDENTITY_OVERCAPTION` и `SETTING_OVERSPECIFIC` берутся из caption policy проекта. Если policy не задана — применяются паттерны по умолчанию.

## Влияние на рабочий процесс

Предупреждения быстрой проверки передаются обратно нормализатору как feedback. Нормализатор видит код и сообщение и пытается написать исправленную подпись. Этот цикл повторяется до исчерпания лимита.

После успешного прохождения быстрой проверки подпись переходит к интеллектуальной проверке.

Подробнее об интеллектуальной проверке — в разделе [Шаг 4: Интеллектуальная проверка](pipeline_llm_checker.md).
