# Шаг 1: Анализ

Первый шаг обработки: аналитик смотрит на изображение и описывает, что на нём изображено.

## Для начинающих

Когда изображение попадает в очередь, аналитик первым берётся за работу. Он отправляет картинку в языковую модель с поддержкой зрения и получает обратно структурированное описание.

Что именно описывает аналитик — зависит от типа LoRA проекта. Для проекта типа «персонаж» он фиксирует позу, одежду, выражение лица и обстановку. Для «стиля» — технику рендеринга, палитру и текстуру. Для «одежды» — крой, материал и конструктивные детали предмета одежды.

Результат сохраняется и передаётся следующему шагу — нормализатору. Сам аналитик не пишет подпись — только описывает.

Подробный список полей для каждого типа — в разделе [Схемы аналитика по типам LoRA](pipeline_analyst_schemas.md).

## Для опытных пользователей

Аналитик выполняет VLM-вызов с системным промптом, подобранным под тип LoRA проекта. Каждый тип имеет отдельный промпт с собственной JSON-схемой. Ответ модели разбирается как JSON. Если разбор не удался, обработчик фиксирует ошибку и делает повторную попытку с повышенной температурой.

Аналитик работает только по пикселям изображения. Промпт генерации, использованный при создании изображения, в запрос к аналитику не передаётся.

Несмотря на различие полей между типами, все схемы содержат три общих поля:

| Поле | Содержимое |
|---|---|
| `raw_description` | Свободное описание изображения в 1–3 предложениях |
| `defects` | Артефакты генерации, анатомические ошибки |
| `uncertainty_notes` | Что аналитик не смог определить однозначно |

Некоторые поля, присутствующие в большинстве типов, используются в быстрой проверке: наличие других персонажей порождает предупреждение MULTI_CHARACTER, взрослый контент на ветке identity — предупреждение ADULT_BRANCH_MISMATCH.

## Влияние на рабочий процесс

Выходные данные аналитика определяют весь дальнейший pipeline. Нормализатор строит подпись на основе этого описания.

Если аналитик вернул неверное описание — итоговая подпись, скорее всего, тоже будет ошибочной. При ревью в таких случаях лучше выбрать «Повторить», а не «Принять».

Подробнее о состояниях изображения — в разделе [Жизненный цикл изображения](pipeline_image_lifecycle.md).
