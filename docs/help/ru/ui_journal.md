# Журнал

Где смотреть события обработки и диагностировать проблемы.

## Для начинающих

Страница «Журнал» открывается по ссылке «Журнал» в навигационной строке. Здесь показаны все события, которые происходили при обработке батчей.

Каждая запись содержит:
- **Время** — когда произошло событие.
- **Уровень** — INFO, WARNING, ERROR.
- **Тип события** — короткое техническое название.
- **Сообщение** — что именно произошло.

Нажав на строку, можно развернуть её и увидеть дополнительные детали: ID проекта, батча, изображения.

Для поиска нужных событий используйте фильтры в верхней части страницы: по уровню, проекту, дате и тексту сообщения.

> **Совет:** если батч завис или изображение застряло в состоянии ERROR — начните с журнала. Найдите записи уровня ERROR по нужному проекту.

## Для опытных пользователей

Журнал содержит бизнес-события: запуск и завершение батча, смена состояния изображения, ошибки LLM-вызовов. Системные операционные логи пишутся в файл (путь задан в настройках) и в журнале не отображаются.

Кнопка «Удалить отфильтрованные» удаляет все записи, соответствующие текущим фильтрам. Это удобно для очистки устаревших логов. Период хранения журнала настраивается в разделе «Настройки» → «Журналирование».

Ссылки `#batchN` в строках журнала — кликабельны; они ведут напрямую к рабочему пространству батча.

## Влияние на рабочий процесс

Журнал — основной инструмент диагностики. При сбое LLM-вызова запись содержит код ошибки и сообщение от сервера. При исчерпании попыток нормализации — запись содержит финальные предупреждения, из-за которых подпись не прошла проверку.

Подробнее о настройках хранения — в разделе [Настройки LLM](ref_llm_settings.md).
