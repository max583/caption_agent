# Параметры проекта

Описание всех полей, которые задаются при создании и редактировании проекта.

---

### Название

**Для начинающих:** произвольный текст — имя вашего LoRA. Например `Denis v001` или `MyStyle`.

**Для опытных:** строка до 255 символов. Должна быть уникальной среди всех проектов в базе данных. Используется как метка в списке проектов и в URL.

**Формат:** строка, обязательное поле, максимум 255 символов.

---

### Описание

**Для начинающих:** необязательное поле для собственных заметок. Никак не влияет на обработку.

**Формат:** произвольный текст, необязательное поле.

---

### Trigger token

**Для начинающих:** уникальное слово, которое будет стоять в начале каждой обучающей подписи. Придумайте бессмысленное слово или комбинацию букв и цифр — например `mychar01` или `xstyle22`. Подробнее — в разделе [Trigger token](concepts_trigger.md).

**Для опытных:** текстовый якорь, активирующий веса адаптера LoRA. Должен быть out-of-distribution относительно базовой модели — не обычное слово из словаря. Caption Agent автоматически подставляет этот токен в начало каждой подписи.

**Что изменится если...**
- Изменить после создания батчей с принятыми подписями — уже сгенерированные подписи останутся со старым токеном; согласованность нарушится.
- Задать обычное слово — модель уже имеет семантику для него; обучение будет хуже.

**Формат:** строка до 128 символов, без пробелов. По умолчанию: `p3rs0n4`.

---

### Тип LoRA

**Для начинающих:** что вы обучаете. Варианты: персонаж, стиль, одежда, лицо, существо, поза, объект. Выберите тип, соответствующий вашему датасету.

**Для опытных:** тип LoRA определяет, какой системный промпт используется нормализатором и какие коды правил активны в быстрой проверке. Например, для типа `style` проверки IDENTITY_OVERCAPTION и STYLE_TOKEN отключены — для стилевого LoRA style-токены допустимы. Подробнее — в разделе [Типы LoRA](concepts_lora_types.md).

**Что изменится если...**
- Выбрать неверный тип — нормализатор будет использовать неподходящий промпт; подписи могут не соответствовать задаче.

**Формат:** выбор из списка: `character`, `style`, `face`, `clothing`, `creature`, `pose`, `object`. По умолчанию: `character`.

---

### Базовая модель

**Для начинающих:** семейство генеративной модели, для которой создаётся датасет. Например `flux` или `sdxl`.

**Для опытных:** используется в контексте pipeline для выбора подходящих настроек. В текущей версии хранится как метка — активное ветвление логики по базовой модели не реализовано.

**Формат:** строка. По умолчанию: `flux`.

---

### Тип источника по умолчанию

**Для начинающих:** тип изображений в новых батчах этого проекта. «Синтетика» — сгенерированные изображения. «Референс» — реальные фотографии или исходные референсы.

**Для опытных:** это значение по умолчанию для новых батчей; каждый батч может его переопределить. Тип источника влияет на активные проверки: SOURCE_REF_PATTERN_VIOLATION включён только для референсов; SLOT_MISSING — только для синтетики.

**Формат:** `synthetic` (по умолчанию) или `reference`.

---

### Ветка по умолчанию

**Для начинающих:** назначение датасета. «Identity» — основная ветка для обучения идентичности персонажа.

**Для опытных:** ветка прокидывается в нормализатор и проверки. На ветке `identity` проверка ADULT_BRANCH_MISMATCH активна: взрослый контент на этой ветке недопустим. Взрослый контент направляется на отдельную ветку.

**Формат:** `identity` (по умолчанию).

---

### Caption policy

Настраиваемые правила подписей для конкретного проекта. Задаётся отдельно через панель «Caption policy» на странице проекта. Подробнее — в разделе [Параметры caption policy](ref_policy_params.md).
