# Параметры caption policy

Описание каждого поля caption policy проекта.

---

### Паттерны признаков идентичности

**Для начинающих:** список описаний, которые нельзя включать в подписи. Если вы обучаете LoRA на конкретного персонажа с серыми глазами — добавьте «gray eyes» в этот список. Подпись не должна называть признаки, которые одинаковы на всех изображениях — иначе модель «запомнит» их как обязательные, а не визуальные.

**Для опытных:** каждая строка — регулярное выражение. Быстрая проверка строит из них общий регекс и матчит подпись. Совпадение → предупреждение IDENTITY_OVERCAPTION. Паттерны не влияют на нормализатор напрямую — только на проверку.

**Примеры:**
- `gray eyes` — серые глаза
- `ordinary body build` — обычное телосложение
- `consistent dark hair` — тёмные волосы одного цвета

**Формат:** список строк с регулярными выражениями Python. По умолчанию — 10 паттернов, описывающих черты персонажа Denis.

---

### Фразы избыточной конкретности обстановки

**Для начинающих:** если одна и та же конкретная деталь фона встречается во многих подписях — модель привязывает её к trigger token. Добавьте такие фразы в этот список, чтобы быстрая проверка предупреждала о них.

**Для опытных:** подстрочный поиск (без регулярных выражений). Совпадение в подписи синтетического изображения → предупреждение SETTING_OVERSPECIFIC. Применяется только к синтетике, не к референсам.

**Примеры:**
- `wooden building` — деревянное здание
- `log cabin` — бревенчатая изба
- `blurred green foliage` — размытая зелёная листва

**Формат:** список строк. По умолчанию — 12 фраз, типичных для датасета Denis.

---

### Обязательная фраза в подписях к референсам

**Для начинающих:** что обязательно должно быть в каждой подписи к реальному референс-изображению. Обычно это описание фона студии.

**Для опытных:** быстрая проверка проверяет наличие этой подстроки в подписях с `source_type=reference`. Если отсутствует → предупреждение SOURCE_REF_PATTERN_VIOLATION.

**Формат:** строка. По умолчанию: `gray studio background`.

---

### Инструкция по обстановке для нормализатора

**Для начинающих:** текст-подсказка для языковой модели: как описывать место действия. Чем категоричнее это ограничение — тем проще модели понять, что «outdoor setting» это правильно, а «in front of a specific crumbling concrete wall» нет.

**Для опытных:** инжектируется в системный промпт нормализатора через плейсхолдер `{coarse_setting_note}`. Пишите в императиве, 1–4 предложения.

**Формат:** строка свободного текста. По умолчанию задаёт принцип «2–4 слова, категория места».

---

### Дополнительные правила нормализатора

**Для начинающих:** если нормализатор постоянно делает одну и ту же ошибку — опишите здесь, что именно должно быть иначе. Этот текст добавляется в конец системного промпта нормализатора.

**Для опытных:** приписывается в системный промпт после основных правил. Нет стандартного формата — пишите как инструкцию на английском языке. Для максимальной силы используйте конкретные примеры или явный запрет.

**Формат:** строка или пусто. По умолчанию: пусто.

---

### Дополнительные правила интеллектуальной проверки

**Для начинающих:** дополнительные критерии для языковой модели-проверщика. Если хотите, чтобы она предупреждала о чём-то конкретном — опишите это здесь.

**Для опытных:** инжектируется в системный промпт интеллектуальной проверки. Независимо от нормализатора — можно задать правила только для проверки, не затрагивая промпт нормализатора.

**Формат:** строка или пусто. По умолчанию: пусто.
