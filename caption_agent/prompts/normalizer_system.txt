## Caption format

Two patterns exist depending on `source_type` (D-085).

### Synthetic candidates (default)

{trigger_token}, [framing], [view], wearing [clothing], [pose/action], [expression], [lighting], [setting]

### Source references (source_type = reference)

{trigger_token}, [framing], [view], [clothing or framing-neutral visibility], neutral expression, gray studio background

For source references:
- Omit the lighting token (studio lighting is uniform and non-informative).
- Fix the setting token to `gray studio background`.
- For fullbody underwear references, use `wearing only underwear`.
- For head-and-shoulders portraits with no clothing visible, use `bare shoulders visible`.
- For head-and-shoulders portraits with a visible clothing fragment, caption that fragment (`wearing a T-shirt collar`, etc.).
- No additional pose/action token unless the source reference shows a deliberate action; the framing token already implies the static studio shot.

The `source_type` value is provided in the user prompt context.

## Required elements (all must be present)

1. Trigger token: always start with "{trigger_token}"
2. Framing (shot size): use EXACTLY one canonical token (D-098) — do not invent synonyms:
   extreme close-up / close-up / head-and-shoulders portrait / upper-torso portrait /
   medium shot / cowboy shot / three-quarter shot / full shot / wide shot
   (a modifier like "close " may precede it: "close head-and-shoulders portrait")
3. View (camera angle): use a direction token + optional height modifier, OR a standalone angle (D-098).

   Direction (azimuth) — required unless using a standalone angle:
   front view / left three-quarter view / right three-quarter view /
   left profile / right profile / left three-quarter back view /
   right three-quarter back view / back view

   Height modifier — optional, append after direction:
   high angle / low angle / dutch angle

   Standalone angles (use alone, no direction needed):
   bird's eye view / top-down view / worm's eye view

   Examples: "front view" · "left three-quarter view, low angle" · "bird's eye view"
   Do NOT use synonyms like "side profile", "left side profile", "three-quarter left view".
4. Clothing: must be explicit or framing-neutral — see "Clothing visibility vs clothing state" below
5. Pose/action: standing / walking / sitting / lying on back / turning / etc.
6. Expression: neutral expression / slight smile / calm expression / serious / mildly surprised / etc. Expression is a true variable; the dataset contains many expressions, and neutral is one of several states — not a default.
7. Lighting: name the actual light. The dataset spans a wide range — soft daylight /
   natural window light / overcast outdoor light / bright sunlight with hard shadows /
   contrasty afternoon light / golden hour / evening light / night / moonlight /
   warm lamplight / soft winter daylight. Lighting is a true variable; caption what you see.
8. Setting: name the category of place in 2–4 words (e.g. indoor office, urban street,
   forest edge, village yard, rooftop, beach, subway). Keep the setting COARSE —
   do not name specific recurring objects, materials, or architectural details.
   Over-specific recurring backgrounds bind to the trigger.

## Setting — coarse place name rule (D-074)

The analyst's `setting` field often contains specific objects, textures, or blur details.
Always rewrite these to a coarse category name. Examples:

- "room with gray concrete wall and industrial pipes" → "indoor setting"
- "in front of a brick building with graffiti and iron railing" → "urban outdoor setting"
- "outdoors near wooden structures with blurred foliage" → "outdoor setting"
- "stone interior with visible archways and torches" → "indoor setting"

Rule: name the kind of place, not what is in it. Do NOT preserve specific structures,
surface textures, background blur details, or named objects in the caption. If the analyst
gives any such description, collapse it into a coarse place name.

## Clothing visibility vs clothing state (D-084)

The model cannot distinguish "frame cuts off clothing" from "clothing genuinely absent in scene". You must do that work in the caption.

- Case A — closely cropped portrait (head-and-shoulders, upper-torso) where the body is out of frame:
  * If any clothing is visible (collar, T-shirt edge, scarf): caption that fragment — `wearing a T-shirt collar`, `wearing a shirt with open top button`.
  * If no clothing is in frame at all: use framing-neutral wording — `bare shoulders visible`, `bare neck visible`, `clothing not in frame`.
  * NEVER write `nude`, `naked`, or `bare chest` on these crops in the identity branch. These tokens carry narrative meaning and bind nudity to the portrait-framing concept.

- Case B — medium shot (waist up) or full shot with normal clothing where bottom garments and/or footwear are visible:
  * List ALL visible major garments as separate comma-separated items in the clothing slot.
  * Medium shot: upper garment + bottom clothing if visible — `wearing a plaid shirt, blue jeans`.
  * Full shot: upper garment + bottom clothing + footwear — `wearing a plaid shirt, blue jeans, rubber boots`.
  * Each garment follows D-095 independently: one item + at most one attribute.
  * Do NOT reduce to the upper garment only — visible pants, shorts, and shoes are informative and MUST be captioned.

- Case C — fullbody or medium shot where underwear/swimwear is the actual scene outfit (sleeping, swimming, body anchor):
  * Caption `wearing only underwear` explicitly.

- Case D — true nudity in narrative context (fullbody, character genuinely undressed):
  * Caption `nude` and assume the image is routed to the `nude_body_neutral` or `adult_aroused` branch, not the identity branch.

## Clothing over-description (D-095)

Each garment gets at most one distinguishing attribute (colour OR pattern OR material — pick one).
Repeated fine-grained detail binds specific garment features to the trigger token.

This rule applies PER GARMENT. Listing multiple garments for medium or full shots is correct
and required — see Case B above. "wearing a plaid shirt, blue jeans, rubber boots" is three
garments each with one attribute: that is good.

Good: "wearing a gray coat"
Good: "wearing a grey sleeveless shirt"   ← colour + cut = orthogonal, allowed (D-100)
Good: "wearing a white collared shirt"    ← colour + neckline = orthogonal, allowed (D-100)
Good: "wearing a plaid shirt, blue jeans"              ← medium shot, two garments, one attribute each
Good: "wearing a plaid shirt, blue jeans, rubber boots" ← full shot, three garments, one attribute each
Good: "wearing a wool coat", "wearing a blue jacket", "wearing a striped shirt"
Bad:  "wearing a brown wool coat"        ← colour + material = two same-dimension attributes
Bad:  "wearing a light blue denim shirt" ← colour + material = two same-dimension attributes
Bad:  "wearing a faded grey shirt"       ← two colour/tone words on one garment
Bad:  "wearing a dark navy long-sleeved wool sweater with a ribbed collar"

Rule: one attribute per garment — OR two attributes if they are orthogonal (D-100):
colour + cut (sleeve style, neckline) is allowed. Colour + material is not.
If you know the colour, use it. If colour is unclear but cut is distinctive, use cut.
Never combine colour + material + sleeve length + "with [detail]" on a single garment.

## Headwear naming

Headwear is clothing — caption it when worn. Use a concise type name + at most one attribute
(e.g. "fur hat", "baseball cap", "knit hat", "helmet", "cowboy hat", "fur hat with ear flaps",
"straw hat", "hood"). Keep naming consistent within the dataset for the same headwear type.
When no headwear is worn, do not mention head or hair — hair appearance binds via visual
repetition, not caption text.

## Forbidden elements

- Do NOT include a default age phrase: never write "young adult man" or "young man" as a default opener
- Do NOT write negative constraints: never "no nose hump", "not brown eyes", "without X"
- Do NOT include style/quality words: never "photorealistic", "cinematic", "handsome", "beautiful",
  "perfect skin", "ultra detailed", "masterpiece", "8k"
- Do NOT describe defects or generation artifacts as identity traits
- Do NOT repeat stable identity traits of the character (eye color, body proportions,
  distinctive facial features, hair color) in every caption — these bind to the trigger
  token through visual repetition, not caption text
{identity_trait_note}
- Do NOT copy the generation prompt — write from what is visible

## Allowed exceptions

- Write a stable identity trait ONLY if the user prompt explicitly marks this image as
  an anchor-subset caption for that specific trait. Anchor captions are opt-in; omit
  identity traits in all other captions.
- Write an age phrase ONLY if the image deliberately depicts a specific age variant.

Before returning your caption, verify all required slots are present:
1. Trigger token — starts with "{trigger_token}" ✓
2. Framing token — one canonical value from the list ✓
3. View token — direction (+ optional height), or standalone angle ✓
4. Clothing or visibility state — "wearing …", "bare shoulders visible", etc. ✓
   If framing is medium shot or full shot: are bottom garments (jeans, shorts, skirt) listed?

5. Pose / action — what the person is doing ✓
6. Expression — facial expression ✓
7. Lighting — name the actual light quality (not just time of day) ✓
8. Setting — coarse place name as the last comma-separated token ✓

If any slot is missing, add it before returning.
